## 先定义问题

此前已经可以记录每项任务返回了什么、还有哪些正文未返回，但工具成功、读到末尾或模型声明 `finish` 都不足以证明约定取证条件满足。本轮解决的是：**用程序逐项检查条件，并返回可追溯的判定和缺口。**

输入：显式 TaskPlan、冻结章节范围、宿主维护的进度、已经核验过的工具返回与证据包，以及本次执行的步数上限。

输出：每项条件、每项任务及整体的工程判定，附具体原因、证据产物/记录/计算 ID、对应执行步骤。语义充分性始终为“未评估”。不读取新来源、不调用模型、不自行查询 内部公司系统。

## 与上一阶段的变化

| 上一阶段能记录的事实 | 本阶段新增的检查 |
| --- | --- |

| 来源或章节不可用，返回 0 块 | 标记受阻，不能把零未读解释为条件满足 |
| 任务声明了依赖关系 | 前置任务的工程条件满足后，才允许执行后续任务 |
| 运行达到步数上限 | 停止执行并保存缺口；不将上限消耗完解释为完成 |

## 实际样例结果

使用与上一阶段相同的明确资料范围和六步操作：Alphabet FY2025 10-K、Business 章节与 Google Cloud FY2025 营业利润率。具体来源和步骤登记在[replay-spec.json](../experiments/data_agent_query/task-completion-v1/replay-spec.json)，不是通用代码的默认输入。

| 步骤 | 动作 | 业务正文已返回 / 总数 | 业务正文判定 | 数字任务判定 |
| --- | --- | --- | --- | --- |
| 1 | 查看目录 | 0 / 79 | 缺证据 | 尚未查询 |
| 2 | 读取前 4 块 | 4 / 79 | 缺证据 | 尚未查询 |
| 3 | 重复读取 | 4 / 79 | 缺证据 | 尚未查询 |
| 4 | 字面搜索 | 4 / 79 | 缺证据 | 尚未查询 |

数字任务返回收入 58,705,000,000 USD、营业利润 13,910,000,000 USD，按注册公式计算为 **23.69%**。这两条记录的引用均能核验到冻结原文，计算输入与输出也通过现有证据校验。

最终整体为 **limited（达到六步上限）**，具体任务仍保留各自判定；`finish_allowed=false` 表示不能声明所有取证条件满足，不表示可以继续超限运行。运行已停止并保存结果。当前样例没有阅读全文，也没有生成完整业务/风险分析。

## 判定规则与实现

新增 `retrieval-task-completion-v1`，将工程判定单独保存。原 `retrieval-task-progress-v1` 继续保存事实及其旧 `not_evaluated` 字段；启用新能力的运行以独立 `completion` 对象作为工程判定，最终结果版本为 `retrieval-task-result-v2`。

| 检查 | 条件 |
| --- | --- |
| 正文范围 | 来源和章节可用，存在正文块。只有图片或布局块的范围不会自动通过正文要求 |
| 正文覆盖 | 与冻结章节清单及真实读取回执一致，未读正文为空；搜索和出处引用不增加正文覆盖 |
| 记录匹配 | 与本要求声明的实体、指标、期间、取值类型一致，选择结果无冲突；每条记录有对应已核验产物 |
| 原文引用 | 主证据、条件限定及问答引用均具有已核验原文父产物和定位信息。只有数据库保存的 quote、没有原文定位时不通过 |
| 计算 | 使用现有注册公式依赖定义；所需输入全部取得且匹配，成功计算结果绑定对应证据产物 |
| 前置依赖 | 所有前置任务的工程条件满足；不能只凭曾执行过前置工具放行 |
| 限额与结束资格 | 全部任务满足后才返回 `finish_allowed=true`；未满足且无剩余步数时整体为 limited |

每项检查返回 satisfied、missing_evidence 或 blocked；整体另有 limited。各项原因和证据引用都保留。历史错误与证据包问题不删除；后续取得证据可以满足相应工程条件，但不会把历史缺口自动标为语义已解决。归一化来源未知、模型元数据缺失等信息仍可作为保留问题存在，不能据工程通过推断提取语义正确。

代码入口：

- [完成判定契约](../src/uteki/domain/research_data/task_completion.py)：校验汇总状态、结束资格和剩余额度一致性。
- [TaskCompletionEvaluator](../src/uteki/infrastructure/research_data/task_completion.py)：消费宿主已核验回执与冻结范围，不接受模型直接写入完成状态，也不执行新查询。
- [TaskProgressSession](../src/uteki/infrastructure/research_data/task_progress.py)：新运行显式设置 `completion_checks=True`；每步原子保存请求、返回、证据包、进度和判定。依赖检查在工具执行前进行。
- `session.check_completion()`：只读检查当前是否满足条件，不能推进进度、重置上限或关闭会话。模型 `finish` 尚未接到此入口，属于 3.4。
- `ScopedQueryDataPort.get_schema()`：通过 `output_contracts.task_completion` 暴露判定 Schema，不改变旧模型动作或冻结数据库 Schema。

- `task-completion-v1/offline-01` 保留首版报告；`offline-02` 只把“允许结束取证”改成更准确的“允许声明取证条件已满足”，避免与达到上限后的停止混淆，两次均为相同额度的离线验证。
- 本轮无浏览器视觉验收、付费调用、内部公司系统 查询或 Git 提交，没有新增核心技术卡点。
