# 任务计划与取证进度：问题定义与交付

后续进展：3.3 工程完成检查已另行实现，见[完成检查报告](DATA_AGENT_TASK_COMPLETION_REPORT.zh-CN.md)。下文保留 3.1、3.2 交付时的范围和原样例结论。

## 要解决的问题

已有读取、查询和证据打包工具，但工具返回尚未与具体取证任务绑定。仅凭返回块数、SQL 成功或 Agent 的 `finish`，无法判断某个需求实际取得了什么、哪里还没读、是否重复统计。

本轮解决可追溯的任务计划和实际取证进度（TODO 3.1、3.2）。输入为显式问题、冻结来源范围和调用方/离线脚本提供的任务计划；输出为任务定义、每次请求与真实返回、证据包、逐轮进度及剩余范围。不会把规则分块视为语义完整，不改变原文或旧快照。

## 边界和验收标准

- 计划记录每项取证要求、来源、期间、依赖和类型化完成条件。正文范围绑定冻结目录；数字期间沿用当前显式日历年/季度支持，不从数据库覆盖猜测。
- 宿主负责执行工具和更新进度；外部输入只能提交请求，不能提交已读集合或任务完成状态。
- 正文进度按 snapshot/source/index/block 定位去重。搜索预览、目录、图片引用、出处核查分别记录，不合并为正文已读。
- 每次只执行一个明确任务的明确要求；取数和计算继续使用已有 SQL generator/executor 和证据校验器，不能跨任务来源。
- 重复读取保持未读集合不变；到达章节末尾不能消除前文空洞。工具失败保留原进度和错误历史。
- 保存不可覆盖的逐轮产物，在同一冻结数据上离线重放，比较真实返回与进度的一致性。
- 此轮不接入模型自主拆题、语义判断或自动完成判定。任务依赖只验证图结构；依赖门控尚未实现时拒绝执行依赖任务，不宣称已支持调度。模型 ReAct 接入属于 3.4。
- 不调用付费模型，不扩展页面验收，不自动查询 内部公司系统。核心技术卡点先明确问题、影响及可选方案，再向用户同步。

## 当前交付

2026-09-23 已完成 TODO 3.1、3.2，并提供[六步可读报告](../experiments/data_agent_query/task-progress-v1/offline-01/README.md)。这是可执行的宿主程序入口，尚未接入 DataQueryAgent 的模型循环。没有开展完整业务/风险问题的研究验收。

| 层次 | 输入 | 处理 | 产物 |
| --- | --- | --- | --- |
| TaskPlan | 原问题、明确来源范围、各项取证要求 | 校验唯一 ID、依赖图、来源子集、显式查询期间 | `retrieval-task-plan-v1`，保留计划来源 |
| TaskStep | 任务 ID、要求 ID、一个类型化工具请求 | 拒绝跨任务来源/章节、擅改查询和直接写完成状态 | 本步实际请求 |
| 执行 | 已校验请求 | 在任务专属来源范围内读取/搜索/查询，核验原文和证据派生关系 | 工具返回、`retrieval-evidence-v1` |
| 进度 | 实际返回与已校验证据包 | 正文按复合定位去重；导航、图片、非正文分别记录 | `retrieval-task-progress-v1`，保留未读集合、游标及问题历史 |
| 保存/重放 | 每次请求、返回、证据包和状态 | 保存新事件目录与文件哈希；在相同冻结数据上重执行并比较 | 可读报告、逐轮事件、重放验证记录 |

每一步的完成状态固定为 `not_evaluated`。这是尚未实现完成评估的显式表达，不会把成功返回记录解释成“任务完成”。已校验仅说明数据与冻结来源/计算相符，不代表原始抽取语义正确或研究证据充分。

## 六步样例：输入是什么，结果是什么

显式选定 Alphabet FY2025 10-K，候选数据允许读取但未采纳，信息截止日为 2026-09-22；不包含电话会、后续季度或网页。问题和步骤登记在[replay-spec.json](../experiments/data_agent_query/task-progress-v1/replay-spec.json)，并未写入通用代码作为默认值。

任务 A 要求取得 Business 章节正文；任务 B 要求取得 Google Cloud FY2025 营业利润率及依据。任务 A 的范围来自冻结索引，共 79 个正文块（包含标题；已标记页码、布局块和图片不计正文）。

| 步骤 | 实际动作 | 实际返回 | 任务 A 已返回 / 未返回正文 |
| --- | --- | --- | --- |
| 1 | 查看来源目录 | 目录节点；导航信息单独记录 | 0 / 79 |
| 2 | 读取章节前 4 块 | 4 个正文块与证据产物 | 4 / 75 |
| 3 | 再读同一批 4 块 | 原块再次返回，去重后没有新增 | 4 / 75 |
| 4 | 在该章节字面搜索 `Our mission` | 1 条预览；没有取得完整阅读上下文 | 4 / 75 |
| 5 | 用步骤 2 返回的游标续读 4 块 | 3 个新正文块、1 个页码块 | 7 / 72 |
| 6 | 执行任务 B 的查询/计算 | 2 条原始记录、1 个计算结果；不改变任务 A 进度 | 7 / 72 |

任务 B 返回的候选记录：收入 58,705,000,000 USD，营业利润 13,910,000,000 USD；沿用注册公式计算出的营业利润率为 **23.69%**。每条记录和计算都有对应 ID 与证据包，SQL 及参数保留在本步工具返回的 `trace` 中。没有让模型生成或改写这些数值。

最终仍有 72 个正文块未返回，任务 A 没有完成。任务 B 虽取得记录与计算结果，程序也尚未进行“引用是否足以满足要求”等完成判定。两个任务都保持未评估；风险章节与完整业务/风险分析不属于本次小样例。

“79 块”只描述当前解析索引中的选定范围，不能证明原始 10-K 解析无遗漏；“7 块已返回”也不能证明模型已理解这些文本。

## 检查结果

- 独立合成公司及真实冻结材料均通过验证。新增 19 项测试覆盖计划约束、任务/来源/期间隔离、正文去重、前文空洞、图片排除、错误保留、不可覆盖输出、保存失败、Schema 发现和重放。
- 改写工具返回的原文时，证据核验失败，进度不增加；保存失败时不发布该步事件，也不推进内存状态。
- 跨来源出现相同 block ID 时，不会合并为同一正文块。对查询取得的原文引用不计作章节正文已返回。
- 实际样例共 6 步，执行错误 0、模型调用 0。重放逐项比较工具返回、证据包、事件和状态，结果一致；执行前后冻结数据文件哈希一致。见[verification.json](../experiments/data_agent_query/task-progress-v1/offline-01/verification.json)。
- 全量离线回归：**619 项 Python + 7 项 JavaScript 检查通过**。执行命令：`.venv/bin/python scripts/run_offline_checks.py --integration`。
- 发现并修复现有显式年份识别的标点问题：`FY2031.` 原先因句末句点被拒绝；现可识别，`FY2031.5` 仍拒绝作为年份。未改变已有期间支持范围。
- 未进行浏览器视觉验收、付费模型调用或 内部公司系统 查询。已有快照和历史运行未重写，本轮文件未提交 Git。

## 如何查看与复现

先读[逐步报告](../experiments/data_agent_query/task-progress-v1/offline-01/README.md)，其中包含任务条件、每步输入、原文、记录、计算和剩余缺口，不需要阅读 JSON 才能理解结果。

程序接入点：

- [TaskPlan / TaskStep / ProgressSnapshot](../src/uteki/domain/research_data/task_plan.py)：计划、请求、进度的 Pydantic 契约。
- [TaskProgressSession](../src/uteki/infrastructure/research_data/task_progress.py)：宿主执行与进度归属、保存和重放。
- [run_task_progress.py](../scripts/run_task_progress.py)：只执行明确登记的离线步骤并生成报告。
- `ScopedQueryDataPort.get_schema()` 新增 `task_contracts` 和 `output_contracts.task_progress`；不修改冻结数据库 Schema，不将任务契约注入旧模型规划循环。

从仓库根目录运行，输出目录必须尚不存在：

```bash
PYTHONPATH=src:. .venv/bin/python scripts/run_task_progress.py \
  --spec experiments/data_agent_query/task-progress-v1/replay-spec.json \
  --output /tmp/uteki-task-progress-review-new
```

`session/` 保存计划与 Schema、初始状态、逐步请求/工具返回/证据包/事件/状态，以及最终结果和哈希清单。进度状态的副本不会反向修改宿主状态。重放需要调用方指定原运行清单哈希，不能通过重写旧文件伪装一致性。

## 下一步：3.3 完成检查

下一步的问题是：如何将实际取证记录转成可核查的工程条件，同时保留语义充分性尚未判断的事实。
