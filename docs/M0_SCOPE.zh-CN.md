# M0 范围——Alphabet 公开披露业务结构

## 状态

供人工审核的草案。本文件定义当前里程碑，但不授权开始实施。中文文件为规范性文件，必须与英文配套文件保持语义一致。

## 评测问题

> 给定 Alphabet 连续三个财年的年度 10-K，在一套固定标注规则下，系统能否完整、无重复地识别公开披露的业务实体，对实体类型进行分类，还原公开披露的业务关系，附上支持证据，并识别披露变化？

## 为什么选择它作为 M0

这项任务直接服务于理解一家公司，并且可以依据第一手材料核验。相比 Thesis、Risk 或业务重要性判断，它的范围更窄、评分更客观，同时仍能检验文档理解、分类、关系抽取、证据归因和变化识别能力。

## 含义边界

产出是 **Alphabet 公开披露业务结构**，不是 Alphabet 的真实内部组织架构。10-K 反映的是面向投资者的报告与描述口径。某个业务或组织单元没有出现在文件中，并不能证明它在公司内部不存在。

## 输入

- 公司：仅 Alphabet。
- 来源：仅第一手年度 10-K。
- 时间范围：连续三个财年，在 G0 固定。
- 文件格式与稳定定位规则：在 G0 固定。

M0 的 Benchmark 来源不包括业绩会、季度报告、新闻、投资者演示材料和外部公司知识。

## 必需产出

### 1. 业务节点

每个纳入的节点记录规范名称和披露名称、从固定分类体系中选择的实体类型、报告财年、原文证据和稳定定位，以及仅用于诊断的抽取置信度。初始分类至少必须区分报告分部、业务线、产品或平台、收入来源。G0 负责定义每种类型并处理歧义。

### 2. 业务关系

业务关系构成 Graph，不一定是严格的树。初始关系分类至少必须区分 `reported_under`、`part_of` 和 `generates_revenue_through`。每条关系都必须有直接证据，或使用有明确文档记录的推导规则。

### 3. 披露变化

跨报告年度的产出必须区分业务变化、报告或分类口径变化、术语或名称变化、仅描述发生变化，以及当文件不足以支持更强结论时标记为未知。不能仅凭文本差异就将其标记为真实业务变化。

### 4. 证据

每个节点、关系和变化判断都必须能够回到原文审核。证据需要记录报告文件、章节或 Item、稳定定位，以及足以支持判断的最小原文片段。

## 标注与 Gold Benchmark

Gold Set 按以下流程建立：

1. 定义纳入、排除、类型、关系和变化规则；
2. 允许高能力模型或 Agent 提出候选标注；
3. 由人工对照 10-K 逐项核验所有候选；
4. 人工独立搜索 Agent 遗漏的内容；
5. 显式处理歧义，而不是隐藏歧义；
6. 将审核完成的数据集冻结为 Benchmark v0.1。

Agent 建议可以提高标注效率，但不能因为多个模型意见一致就自动成为 Ground Truth。发布的 Gold Set 由第一手证据和人工裁决共同决定。

## 初始指标

- 节点 Precision 和 Recall；
- 实体类型 Accuracy；
- 关系 Precision 和 Recall；
- Duplicate Rate；
- Evidence Support Accuracy；
- 变化类型 Precision 和 Recall；
- 无效输出率和 Abstention Rate；
- 作为诊断指标的成本和延迟。

指标还必须按照报告年度、实体类型和错误类别分别统计。只有一个聚合分数是不够的。

## 明确不在范围内

- 真实内部组织架构；
- 业务重要性排序；
- 业务动量或未来潜力；
- 财务指标抽取；
- 投资 Thesis、Risks 和 Variant Perception；
- 公司发现、跨公司比较和组合管理；
- 冻结 10-K 集合之外的来源；
- 精致的标注界面或对外产品界面；
- Benchmark v0.1 和 Baseline 冻结之前的优化。

这些是后续里程碑，并不是被否定的能力。

## 五道 Gate

### G0——标注契约

冻结报告年份、文档表示方式、定位规则、纳入与排除规则、节点分类、关系分类、变化分类、歧义处理和评分规则。先人工标注一个极小 Pilot，并在生产完整 Gold Set 前修订契约。

### G1——Gold Benchmark v0.1

为冻结的报告文件创建并审核完整 Gold Structure。保留原文证据、标注者决策、排除项和未解决歧义。Benchmark 规模使用节点、关系、变化和证据记录数量衡量，不人为规定问题条数。

### G2——未经调优的 Baseline

使用最简单可行的旧 Data Agent 路径或重建路径运行，不得根据完整 Benchmark 调优。冻结模型、Prompt、配置、代码版本、原始输出、Trace、成本和延迟。

### G3——评测与错误分析

对 Baseline 评分，并人工检查每一个 False Positive、False Negative、重复节点、无证据关系和错误变化分类。区分数据源、解析、Ontology、抽取、规范化、证据、时间对齐和 Benchmark 本身的错误。

### G4——Experiment 001

选择一个影响较大的错误类别，写出可证伪的假设，只改变一个因素，在相同 Benchmark 上重新运行，并记录质量、成本及其权衡。

## 停止条件

出现以下情况时暂停并返回 G0：两位认真审核者无法一致应用某条规则；某项无法根据证据核验；某个变化判断无法区分文本变化和真实业务变化；或者在 Benchmark 与未调优 Baseline 冻结前，实施范围已经开始膨胀。

## M0 之后的扩展规则

每次只扩展一个维度：

1. 固定任务，将它应用到一个小规模公司集合；
2. 先稳定跨公司表现，再增加公司数量；
3. 每个新研究问题首先在 Alphabet 上验证；
4. 再将已经验证的新问题扩展到既有公司集合；
5. 只有当真实错误和业务价值证明下一阶段扩展合理时，才逐步扩大到 10、50、100 家公司。

公司数量是方向标，不是交付指标。每次扩展都需要根据 Benchmark 质量和泛化表现设置明确 Gate。
