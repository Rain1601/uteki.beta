# 研究数据质量：逐步优化与结果对照

日期：2026-09-22。对应 [数据质量评估与技术方案](RESEARCH_DATA_PIPELINE_TECHNICAL_PLAN.zh-CN.md)。Step 1–4 已完成局部实验，另有 [12 次抽取 prompt 实测](CLAUDE_EXTRACTION_PROMPT_REPORT.zh-CN.md)；Step 5 已调用，因截断及重跑连接错误尚未完整验收。

目标：每做一项优化，都能看到相同研究问题下的真实输入、结构化结果、证据和变化，而不是只看最终报告或整体评分。长期架构保持不变，每一步由具体缺口和实测结果决定是否继续。

## 1. 当前状态与比较方式

- Step 0 已保存现有输出和来源/代码指纹，见 [现状快照](../experiments/research_data_quality/2026-09-22-step-00/README.zh-CN.md)。这是历史产物的固定副本与现状记录，没有重新运行模型，也不是已完成独立标注的质量基线。
- Step 1–4 已按下表执行局部实验。DeepSeek 已配置并完成真实调用；新增 Step 3b 为基础/Claude 改写 prompt 的固定模型抽取对照，12 次已完成。Step 5 首轮 8 次有 1 次截断；重跑第 4 次连接失败且费用未知，后续停止。本轮不作模型供应商对比。
- 当前已有 Cloud 从原始表格抽取的实现，必须纳入 baseline；不能只挑更弱的旧 claim 打包器作对手，将已有能力记成本次提升。
- 每个完成的步骤同时比较 **当前尝试 vs 父版本**、**当前尝试 vs Step 0**。父版本是明确选定的前一版本，不一定是上一次尝试；无改善、退步、跳过都保存原因。
- 更换来源、模型或评价规则，建立新的实验分支。双方必须在相同来源及规则上重跑，才报告对应增益；不拼接不兼容分数。

## 2. Step 划分

| Step | 单一改动主题 | 你会看到的真实结果 | 核心判断 | 当前状态 |
| --- | --- | --- | --- | --- |
| **0：现状** | 保存当前可用材料、实现和输出，不改算法 | 当前 Cloud 年度指标、旧包与 source-first 路径的证据形式、已有读取实验；覆盖与尚未测量项 | 清楚知道今天已有什么，以及哪些能力尚未验证 | 现状快照已保存；独立参考、模型配置及完整评价基线未冻结 |
| **1：财务记录** | 将现有年度数值的金融上下文表达清楚；复用原单元格/XBRL | 同一批年度数值的前后记录，逐项展示 period、unit、dimensions、basis、locator 的变化；金额未变也明确标出 | 是否保留数值且更准确表达上下文，能否检测错单位/错主体；字段变多本身不算质量提升 | 已执行，6/6 年度值未变 |
| **2：季度与累计** | 在相同契约下处理季度/YTD/时点及序列身份 | Q2 三个月与六个月的独立记录，Q1/H1 推导的单季 Capex、缺口矩阵与拒绝的不可比运算 | 是否混期、混口径；披露值与计算值是否清楚分开 | 已执行，18 条新增记录、2 项计算 |
| **3：电话会语义** | 基于已有完整 turns/Q&A 生成最小陈述与 Guidance 记录 | 同一问题的旧读取结果与新记录；原话、说话人、条件、指引期间、问答入口 | 是否漏条件、把预期当实际、把提问当公司事实；未抽出的重要陈述单列 | 已执行有限规则实验，35 条陈述、2 处指引、5 组问答 |
| **4：证据语境** | 只修前几步实测的读取遗漏或语境缺失 | 受影响案例的前后完整表格/附注/列表/Q&A，以及未受影响案例的回归 | 源中有但没读到，还是读到但没理解；没有发现读取问题则跳过 | 已执行指引关联修复，保留一次过度补读尝试 |
| **3b：抽取 prompt** | 相同来源/schema/模型，比较基础与 Claude 改写指令 | 12 次真实结果、逐项引用/数值/语义复核及费用 | 能否改善结构化抽取 | 完成局部实验；单位/部分限定关联改善，数值无额外提升，共同契约缺口仍在 |
| **5：Agent 消费** | 固定分析模型，将输入从当前方式切为结构化数据与可展开依据 | 相同研究问题的两份真实回答、引用、错误/遗漏、补读次数、token/费用与人工复核耗时 | 数据改进是否实际改善下游可靠性与复用 | 已实际调用但未完整验收；重跑因连接错误/未知费用停止。固定输入方案，不测试自主补读 |

每一步若包含两个可独立改变结果的机制，拆成 1a/1b 等子步骤。例如先结构化财务 context，再扩展读取范围，不能一次同时换模型、Prompt、检索和 schema 后只归因于其中一个。

Step 1 的数值不必改变才能有价值，但仅把 `FY2025` 变成 JSON 字段不构成充分收益；必须证明字段有来源支持，并能用于正确查询、校验或拒绝错误。Step 2/3 中旧路径未支持的能力标记为 `not_supported`，单列新增覆盖，不能伪造旧错误率为 100%。

Claude/GPT 模型对照放在处理管线稳定之后，作为独立实验；供应商数据对照也单独进行。它们不混入上述处理方法的累计增益。

## 3. 固定材料与研究问题

第一组材料：Alphabet FY2025 10-K、2026 Q1/Q2 10-Q、2025 Q4 电话会及发布稿。它们不是同一季度的一套材料；电话会验证其自身披露与指引，不能代答 2026 Q2 管理层说法。

Step 0 捕获时，前四份材料通过原文/索引 hash 检查；Q4 发布稿的本地原文与清单/索引声明不一致，已单独记录并暂时排除。当前比较先用其余四份材料；发布稿完成来源核对后，以新实验版本加入，不能悄悄改变前后输入。详情见 Step 0。

固定问题草案：

| Case | 问题 | 应检查的内容 |
| --- | --- | --- |
| F1 | Cloud FY2023–FY2025 收入和营业利润分别是多少？ | 六个指标值、期间、USD millions、主体及原单元格；当前已有可用结果 |
| F2 | 2026 Q2 季报中 Cloud 的单季与年初累计指标如何区分？ | 三个月/六个月、去年同期、期间长度及相应证据，不使用字符串年份猜测 |
| F3 | Alphabet 的 Capex 哪些是累计披露，哪些单季值需推导？ | 预先确定 Capex 定义；H1 与 Q1 同口径；公式及操作数；不归为 Cloud 分部 Capex |
| T1 | Q4 电话会上管理层给出的资本开支指引是什么，适用何时，有哪些限定？ | 实际原话、speaker、条件、未来期间；数值与定性指引分开；无披露则明确缺失 |
| T2 | 对所选 Cloud 问题，管理层实际回答了什么？ | 在看模型输出前，从源中选定 exchange；完整问题/回答/追问；分析师断言不成为公司事实 |
| A1/A2 | 基于上述证据解释 Cloud 经营变化、区分资本开支实际值与指引 | 两个真实消费任务；可复算数字、证据与限制；不能用不匹配季度作同期互证 |

运行前冻结具体 case ID、原文范围、目标指标/主题、允许推导、缺失定义和不参与调优的保留样本。独立从源材料建立参考；不能直接把某个模型的输出当作 Gold。当前 snapshot 是已有结果，不是这组未来问题的完整参考答案。

## 4. 每一步的结果页要回答什么

复用项目已有的“先结果、再展开证据”的阅读顺序。每步结果先展示：

1. **这一步改了什么、为什么改。** 对应一个已登记的问题和精确版本差异。
2. **前后实际结果。** 同一 case 左右展示字段/数值或真实回答；按业务键对齐，不按数组位置或新旧 ID 硬比。
3. **有意义的变化。** 新增、修正、移除、未变、冲突、缺失分别列出；每项可展开原文。新增记录不自动记为正确，移除记录不自动记为退步。
4. **质量与代价。** 数值及口径正确性、原话归属、遗漏、证据完整性、补读次数与资源用量。分别呈现机械检查和人工语义复核；没有测量就写“未测”。
5. **结论与下一步。** 改善、无显著变化、退步或证据不足；下一步采用哪个版本、仍有哪些未知。保留候选身份和原审核机制。

同时提供相对 Step 0 的累计视图。旧答案若只是沿用，明确标记“沿用，非新模型输出”；只重放工具调用时，不声称回答质量、模型 token 或模型费用已经改善。

现有 `scripts/render_context_comparison.py` 和 `scripts/render_analysis_comparison.py` 提供展示参考，但不是现成的逐步实验 runner：前者沿用旧答案，后者比较 Single/Team 且预算不同。正式页面需读实验 manifest 和实际产物，不能把这两类历史实验直接当成本轮公平 A/B。

## 5. 版本、产物与对齐

每次尝试有不可变目录，例如 `experiments/research_data_quality/<experiment_id>/step-01/attempt-01/`。后续执行时按真实产物建立，当前不预建空目录。

```text
manifest.json        来源/索引/代码/Prompt/schema/model/预算/父版本与基线身份
cases.json           冻结的任务及允许来源；不含 Gold
input.json           实际送入处理路径的数据与读取配置
output.json          原始结构化输出；失败也保留
evidence.json        确切引用、表头/单位/附注/完整问答入口
validation.json      机械检查与 unsupported 项
diff-parent.json     与父版本的结果差异
diff-baseline.json   与 Step 0 的累计差异
metrics.json         指标分子/分母、未测项、用量与费用状态
REVIEW.zh-CN.md      结果、证据、错误归因及人工审核记录入口
```

执行侧只读 sources/cases；参考答案、评分和人工审核属于评测侧。版本不覆盖，人工采纳不因上游改动自动继承。

跨 schema 对齐用独立评测适配器，比较 entity + metric + start/end/instant + period kind + dimensions + currency/basis；同时保留 source occurrence 和版本。无法对齐的项列为未匹配并核查，不自动视为新增正确记录。验证器若修复评分错误，对新旧输出按同版规则重评。

模型实验记录实际请求配置、响应、运行次数和预算。重要案例进行预先登记的重复运行，呈现波动，不只挑最好一次。重复次数在运行前按预算固定；未确定预算前不执行收费对照。
