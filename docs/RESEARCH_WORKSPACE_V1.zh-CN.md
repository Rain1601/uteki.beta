## 1. 范围与责任

目标：形成可追溯、可修正的企业研究档案，回答我们相信什么、依据是什么、新证据改变了什么、何时应承认未知或判断失效。

本轮只做 Alphabet；保留 Single 与 Team，不预设优胜者。效果标准由助手提出、用户审核；交互由用户设计，助手实现确认后的规则。旧版仅作参考，不移植其数据、结论或复杂架构。companies 列表保持不变。

本方案不新增交易、持仓操作、自动定时任务、新公司采集、数据库或前端框架；仅实施已确认规则，不新增付费模型调用。原始 Data Agent 与分析判断分层保持。

## 2. 问题与产物

主开发题：Alphabet 未来 3–5 年最重要的增长驱动与下行风险是什么？哪些业务变化会影响价值？判断股价影响还缺什么？

用户认可“Cloud 扩张并改善利润率，同时 AI 搜索/广告未被显著稀释”为候选假设，不是标准答案。不把该结论注入独立测试的提示词。当前规模、增长率、绝对增量、经济回报、市场预期必须分开；排序属于推断。

每次产物包括：直接回答、关键假设、支持/反对证据、未知项、验证计划、相对基线的变化。Thesis/Drivers/Risks/To Watch 是可选呈现，不是大师认证方法，也不强制产出买入观点。

## 3. 效果验证协议

### E1 运行前冻结

记录问题版本、材料及索引 SHA、主材料、所有来源发布时间、可用信息截止时间、提示词/代码/模型/供应商版本、上游路由是否可核实、工具/Token/时间预算、上下文清单与人工意见版本。旧实验不覆盖。

先做离线契约测试；用户审核后才执行付费对照。开发题每模式重复 3 次，全部报告，失败也保留；不是统计显著性研究。另准备 2 道保留题：用户或独立评审者保管，在冻结方案后运行，使用后转为开发题。若助手已接触题目，不称对助手隐藏。

### E2 三层验证，不混成准确率

1. 证据：来源存在、成功读取、版本/时间正确、原文绑定、表格单位/期间/行列正确。来源完整不等于语义支持。
2. 论证：回答未来驱动；区分规模与增量；解释经济机制；区分事实/推断；处理反证；给出可执行验证点；区分公司价值与股价预期。
3. 兑现：冻结假设后按未来披露更新。历史回放用于过程测试，模型可能知道未来，不冒充前瞻预测效果。价格上涨不等于假设兑现。

### E3 审核方式

先用现有真实结果和 2–3 个正反例校准标准，不立即重跑。运行完整性和上下文纪律是独立门槛；用户适用性（偏好、可读性、审核时间）单列，不计入事实正确性。错误同时记录类型、严重度、独立根因和引用出现次数，避免把同一错误重复十次算成十个独立错误。

逐项通过/部分通过/不通过/无法判断，附理由和引用；不用综合分数掩盖严重错误。展示通过项/适用项、覆盖缺口、关键错误清单、费用/耗时分布。资料缺失时合理拒答是有效表现。

人工盲评隐藏模式、模型与成本，随机左右顺序；先评质量再揭示成本。记录作者身份可能由内容推知，盲评非绝对。用户是投资偏好审核人；事实争议回到来源，不以喜好表决。重要或有争议判断可加入第二名独立审核人；未双审时标记单人审核，不宣称一致性已验证。LLM judge 只能辅助发现问题。

单次运行应完整留存成功、失败、取消、预算拒绝事件。费用未知不记零。Single/Team 的实际产品预算对比与等预算对比单独报告；若改变证据接口和预算等多个变量，不能作单变量因果结论。

### E4 验收与回归

进入“可采纳候选”前：无未读取/不存在引用、无主材料或截止时间错误、无未标记的严重数字/语义矛盾。通过程序检查只表示可人工审核，不表示研究正确。

核心论证还需用户审核。错误没有消失就明确保留失败状态，不删除困难样本。每个已发现错误建立回归案例：历史规模替代未来驱动、披露新增冒充业务诞生、AI 提及频次冒充贡献、用户观点被当作事实、市场预期缺失却给出股价断言。

## 4. 公司页与证据交互

P1：/companies 不变。/companies/alphabet 两个主 Tab 已确认：研究档案、公司数据。用 URL 保存 tab 与 snapshot，刷新和分享能恢复选择。

P2：研究档案左侧为快照时间线，右侧显示选中结果。正文优先展示当前判断、与基线的差异、假设和证据、未知项、验证计划、人工意见；运行日志和费用在次级展开区。高信息密度、减少卡片、中英文 UI 沿用；不是复制旧版侧栏和公司池。

P3：公司数据包含原始材料、结构化事实、业务语义结果。主工作流是“提取字段/业务节点 ↔ 原文证据”：点名称、描述、数值或关系，在右侧定位；多出处显示编号及摘要，切换保持所选证据。财务展示保留年份、单位、行列；翻译注明辅助译文，英文来源才是引用基准。

P4：Document Index 不删除，作为材料详情中的次级目录/调试工具；既有深链接继续有效。它不是用户主要分析结果页。缺语义提取结果的文档明确显示“仅已索引”，不得用其他报告结果冒充。

## 5. 快照、时间与状态

S1：原始运行产物不可变。人工编辑创建新修订，保留原模型输出、父版本、差异、作者和时间；只有未采纳修订可编辑。已采纳版本不可编辑，归档后如需修改仍创建新修订，不重写历史。

S2：列表按主材料实际公开时间倒序，而非报告期结束日；同一主材料下按运行开始时间倒序，再以内部 ID 打破并列。显示版本号到分钟（Asia/Shanghai），同分钟加短 ID 消歧；存储 UTC 高精度时间和唯一 run_id。分析主语料由运行前明确选定；多文档运行指定 primary_document_id，并完整列出其他材料。

S3：另存 knowledge_cutoff=max(本次允许的来源/继承内容可用时间)，不得用主材料时间伪装较晚信息。无法核实发布日期的材料标记不确定，不进入严格时点回放。

S4（已确认按主题限制）：同一 company + research_scope + primary_document_id 最多一份已采纳修订。Single/Team 竞争同一采纳位；模型和索引版本变化不创建额外采纳位。采纳须显式操作，并在一个事务中归档同组其余候选，返回状态变化清单。既有已采纳项存在时禁止静默替换；先归档再采纳。用原子唯一性检查防并发双采纳。

状态转换：未采纳→采纳/归档/删除；采纳→归档；归档→采纳（校验唯一性）/删除。未采纳和归档都可派生编辑修订。删除建议是可恢复软删除，不进入上下文；已采纳需先归档再删除，避免无意移除当前基线。永久删除不在 v1。

S5：采纳≠真理，归档≠错误，删除≠对历史执行内容的抹除。所有动作记录事件、操作者、原因和前后状态。历史运行的 context manifest 不追溯改写；删除/归档只影响之后构建的上下文。

## 6. 上下文继承与人工意见

C1（已确认）：同研究主题下、符合时点约束的最近一份已采纳快照作为基线，更早已采纳历史按需获取；不是把所有已采纳全文拼入。基线必须同时满足知识截止时间与意见可用时间约束。显式区分：严格历史回放、今天对历史材料的研究、实时连续跟踪。历史访问仍须遵守当前采纳状态，已归档内容不通过默认研究工具载入。

C2：默认工具只返回当前可继承的已采纳内容。未采纳、已删除、已归档结果不自动载入；历史审计需用户显式选择单独工具，不偷偷注入已排除结果。新运行开始时冻结上下文清单；运行中发生归档不改变已启动运行，结束后提示基线状态已变化。

C3：归档/删除祖先不能自动消除已经写进后代的判断。保留 lineage，对受影响后代标记“需复核继承意见”，下一次运行告知撤回事项；不宣称可以让模型忘掉已经读取的内容。

C4：人工意见附着 snapshot，独立版本化。区分研究偏好、事实主张、投资假设；保留用户原文和系统建议分类，分类不确定时让用户确认。建议意见显式设置“带入后续”，并仅从已采纳快照载入；归档/删除后停止继承，另保留审计记录。跨快照长期偏好另设独立开关，默认关闭。

C5：每次继承意见都重新判断为：偏好/有证据支持/受到挑战/无法验证/超出当前材料范围，附来源与理由。用户说“Services 更重要”时先识别重要性维度和期限；不能顺从地当事实，也不能仅因和模型观点不同就判用户错误。偏好不能覆写数据、屏蔽反证或突破截止时间。

系统保证意见有审查状态和依据，不承诺一定识别人类错误。未完成检查必须标记“本轮未重审”，不能展示为已验证；这类实质判断不应静默支撑新结论。

C6：上下文打包记录每条选择/排除理由、Token预算和未加载项目；过长时先提供摘要及引用入口，明确分页，不静默截断。运行输出列明本次采纳、拒绝或保留了哪些人工意见及理由。

## 7. 变化与追踪

用稳定 hypothesis_id 连接假设，不以文字是否相同匹配。每个假设含陈述、业务范围、期限、证据、反证、可观察量、重审条件、状态和更新时间。

结果相对显式 baseline_snapshot_id 比较：新增/加强/削弱/失效/仍未知/不再覆盖。每项标明变化原因属于新材料、分析解释、人工修订或模型/提示词变化；相同材料换模型不应伪装为新业务变化。无基线显示首份研究，不制造 diff。

未知没有解决、未发生反证，都不自动记为假设得到验证。重审条件基于业务理由制定，不随意设置阈值。未来披露更新需人工审核，不自动交易。

## 8. 分期与验收

V1-A 先确认规则和双语方案，离线测试状态机、上下文资格、时间排序、同分钟冲突、并发采纳、删除恢复、意见分类和祖先撤回。

V1-B 用现有真实结果接入公司页两区及主材料时间线，实现证据双栏。companies 和原有 /result、索引、实验深链接回归不变。不复制旧版事实或数据。

V1-C 按冻结协议运行最小 Single/Team 对照；新增付费调用前确认预算。归档旧结果，不以用户偏好作为正确答案。

V1-D 做一次新材料引起的假设更新，以及一个“错误人工意见”压力测试；验证系统会提示冲突，原快照不变。界面审核与效果审核各自验收，不互相代替。

## 9. 已确认事项

已确认：最近一份已采纳＋按需历史；按研究主题分别限制采纳；先方案、review 后实现。

补充确认：软删除、编辑派生修订、两个主 Tab、意见“带入后续”开关及归档后的意见处理。后续模型运行仍单独确认预算。

## 10. 当前交付与保留差距

已实现：公司两 Tab、四份历史候选导入、状态与审计原子持久化、编辑派生与复核、意见版本与撤回、上下文资格与清单冻结、受限历史读取、同页原文抽屉及精确 Block 高亮。历史主材料按成功读取次数推定并显式标记，采纳时需确认；不改旧模型输出。

## 11. 交互验收样例（待 review，不是真实操作）

### A. 从两份候选中采纳一份

同一主材料、同一研究主题下有 Single A 与 Team B。点击 A 的“采纳”，先列出校验状态及“B 将归档”的影响；确认后 A 采纳、B 归档。下一次运行只把 A 作为默认基线。换模型或解析版本不会产生第二个采纳位。

当前真实 v0.2 的 Single 仍有一个未读取引用：用户可以认可其思路、写意见，但不能把它直接标为通过验证。先生成证据修复或人工修订版本，再采纳 exact revision；不能因喜欢结论而跳过来源错误。

### B. 修改和撤换

已采纳 A 不显示直接编辑操作。先归档 A，释放采纳位；此时可以采纳 B，或从 A 创建人工修订 A-r2。A 的原模型答案保持不变。恢复已删除记录建议回到归档状态，绝不自动恢复采纳，以免覆盖当前选择。

### C. 人工意见如何传递

用户在 A 下写“更关注 Cloud 的未来增量，而非只按当前收入排序”。系统保留原文，建议识别为研究重点/偏好；选择带入后续后，B 的 context manifest 引用意见 ID 和版本，B 仍需独立检查 Cloud 证据。

若写“Cloud 2025 收入超过 Services”，系统应以对应年份表格提出事实冲突，不能默默改数字。若写“Services 更重要”，须澄清当前利润、未来增量或风险暴露的维度，不能直接判人错。

为避免下一代基线替换后意见丢失，继承意见的审查结果需携带原 comment_id；B 被采纳后，可继续携带仍有效的已选意见引用，而不是复制成无来源新事实。用户撤回原意见时，所有携带它的后代标记复核并停止以后自动携带；历史执行清单不重写。此项规则已确认。

### D. 时间排序与历史边界

同一 FY2024 10-K 的 A/B 位于该文件公开时间的同一组，组内按实际运行时间排序。若 A 同时读取了晚于该文件的季度报告，列表仍属于主材料组，但显式展示更晚的材料截止时间和“回顾分析”标签。

严格时点分析由工具排除晚于截止日的材料、意见与历史结果；事后产生的研究不能伪装成当时存在的记录。没有时间适格的基线时从原始材料开始，并标记无基线。

### E. 新材料来了之后看什么

新快照顶部明确“相对 A”。同一假设 H1 若被新证据挑战，显示旧判断、新判断、改变理由及两边证据。仅模型表达改变，标记解释变化；本轮没研究 H1，标记未覆盖，不自动记为失效。用户本次 review 应能回答“哪条观点变了、为什么变、是否同意”。

### F. 数据和证据

在公司数据选中一份材料，点击提取字段，右侧展示该材料对应原文和高亮；第二个引用来自另一份报告时，明确切换文档标题/版本，不只滚动位置。打开目录检查再返回，应保留材料、字段与引用选择。没有提取结果时显示仅索引，不伪造业务结构。

### G. 功能验收与效果验收分离

离线功能验收：双窗口并发采纳不能产生两份已采纳；删除恢复不恢复上下文权限；运行中状态变更有提示；每个读取/拒绝事件可追溯。

分析效果验收：同一问题匿名比较原始答案；合理支持 Cloud 或 Services 均可通过，标准是证据与论证而非业务排名。错误意见压力测试不能把“总是反驳用户”当作成功。
