# v0.2 执行计划：M0 可复现研究基线

## 1. 版本任务书

- 状态：已获准进入开发，当前执行 R2-A，尚未验收；任务勾选均需对应交付证据。
- 版本目标：在一份固定 Alphabet FY2025 10-K 上，得到人工可审核的业务地图，建立可靠的参照、baseline、逐项错误分析与一次对照实验。
- 对应既有里程碑：[M0 的 G0–G4](../M0_SCOPE.zh-CN.md)。现有 [G0 Pilot 契约](../G0_CONTRACT.zh-CN.md)是起点，不能直接视为已冻结标准。
- 研究问题：公司主要业务是什么、如何赚钱、彼此是什么关系、哪些披露具有经济重要性、哪些问题仍不知道？
- 完成定义：第三方按说明能取得批准的输入、复算冻结产物的评价，并看清每个重要错误及人工处置；不要求模型已经达到高准确率。
- 输入范围：Alphabet FY2025 10-K，Accession `0001652044-26-000018`。不引入其他年份材料为本版 Gold 作答。
- 角色：执行者负责实现、资料处理、实验和记录；项目负责人负责范围及真实人工研究验收。两种职责不能通过 Agent 自评互相替代。

产品版本 v0.2 与现有 `v0.2-candidate` 数据目录无对应关系。新 source/index/benchmark/run/release 各自使用明确身份和版本；不得用产品版本覆盖旧数据。

## 2. 范围与投入边界

本版交付四个核心产物包：

1. 固定来源、来源处理记录及 G0 契约。
2. 人工 Gold、逐项处置及独立遗漏检查记录。
3. 冻结 baseline、确定性评测入口和完整错误清单。
4. Experiment 001 的事前假设、单因素差异、对照结果和结论。

只实施服务这些成果的最小架构整理：来源访问边界、Agent 公共输入输出、运行记录与评测隔离。保持公司名单、既有研究状态和原始产物不被覆盖。

[六类 Agent 职责提案](../AGENT_SYSTEM_DESIGN.zh-CN.md)作为长期边界参考：公司发现、研究分析、组合/资金、风险和交易执行按后续版本逐步验证。本版 V2-05 仅冻结当前业务地图任务的数据输入输出与评测隔离，不为远期角色预建空框架；十二项任务与验收条件保持不变。

Analysis 已明确需要持续 Watch / Review / Update 和团队协作。本版公共契约继续将输入、配置、结果与运行记录分开，不把消费者绑定到单个模型会话；持久化研究状态、领域任务依赖、跟踪计划与团队复核在 v0.3–v0.5 按路线图验收。本版不新增调度器、常驻 team 或跨期分析验收要求。

季度跟踪产品化、财务预测、情景估值、组合决策、多公司扩展及全面界面重做属于后续版本。旧环境的所有历史实验全绿不是本版发布门槛；本版新增真实 M0 流程必须完整验证，旧缺口继续独立记录。

不在资料暂缺时无限等待旧环境。建议将旧资料排查限制为一个工作日的投入窗口：无法恢复后，记录缺失结论，转向官方来源构建有完整来历的新候选。这个窗口是投入上限建议，不是已排期或交付承诺。

若同一申报文件重新取得的字节与旧指纹不同，保存新原文、获取时间和差异，不冒充旧快照；经来源核对和范围记录后，在新快照上重新标注、评测。若必须更换申报文件，则更新 M0 输入约定后再继续。

## 3. Milestone 与顺序

| 里程碑 | 对应 Gate | 结束时必须能展示 | 不满足时的动作 |
| --- | --- | --- | --- |
| **R2-A 可信来源与任务契约** | G0 | 完整固定来源；第 90 段问题的有证据处置；可解析的来源定位；人工小节试用过的纳入/排除/推导/歧义规则 | 来源无法证明则不进入 Gold；规则冲突则调整契约，再试同一小节 |

任务映射：R2-A 对应 **V2-01～05**；R2-B 对应 **V2-06～07**；R2-C 对应 **V2-08～11**。**V2-12** 在三个里程碑的证据齐备后负责正式版本签收。

## 5. 验收与评价口径

### 5.1 必须通过的完整性与工程检查

| 编号 | 硬性标准 | 如何验证 |
| --- | --- | --- |
| H1 | 本版选定的来源和人工 Gold 无未解释的文件/文本指纹冲突 | 清单逐文件核验；Gold 中每个引用解析到固定原文；引用数与成功数都记录 |
| H2 | Gold 的每个候选项有真实人工处置；做过额外遗漏搜索 | 标注记录与人工确认；未决项不混入已确认答案 |
| H3 | 基线和实验输入、配置、产物与失败均可追溯 | 运行清单包含代码 revision；有未提交改动时必须另存完整 patch 或源码快照及指纹 |
| H4 | 从同一组冻结产物重放，评分和错误清单一致 | 在第二个独立环境或全新目录执行记录的命令，比较规范化结果；不要求重新调用模型逐字一致 |
| H5 | 非法/缺失/错误预测可区分，不能静默删除失败项 | 有针对性的负例；原始 baseline 可包含错误，它们必须完整进入错误清单 |
| H6 | 运行时 Gold/审核决定隔离；候选与采纳边界保持 | 来源白名单负例、跨命名空间拒绝、未经审核修订不能采纳、版本冲突等检查 |
| H7 | 新增本版真实流程回归及已有核心回归通过 | 记录命令、环境、完整结果与覆盖边界；不得缩小范围后声称旧历史集成已通过 |
| H8 | 一次事前登记的单因素实验已完成并如实归档 | 使用同一参考集，保留所有尝试和成本，结论可以是支持、否定或不确定 |

H1 约束批准的来源/人工参考，不要求低质量 baseline 的每个引用都正确。baseline 的无效引用应触发 H5 的检测并阻止不当采纳，不能为通过 H1 而删除错误输出。

### 5.2 研究质量分开报告

| 维度 | 口径 | 谁判断 |
| --- | --- | --- |
| 主要业务覆盖 | 命中的已冻结必需业务数 / 必需业务总数；同时列遗漏项 | 冻结匹配规则；模糊匹配需记录人工裁决 |
| 陈述与经济性正确性 | 每条陈述为支持、部分支持、不支持或无法判断；报告各类别数量 | 人对照固定来源复核；不把“有引用”视为“引用支持结论” |
| 关系正确性 | 关系类型、方向和经济含义分别检查，逐项记录 | 规则检查加人工语义复核 |
| 证据定位 | 可解析且 exact quote/文本指纹正确的引用数 / 总引用数 | 程序检查；引用的语义支持另列 |
| 重复与无证据主张 | 分别报告数量、分母和条目；不只提供一个综合分数 | 规则检测加人工裁决 |
| 未知与不合理推断 | 是否承认缺口、是否把未披露当否定、是否把预测写成事实 | 人工复核，重大项逐条说明 |
| 研究有用性 | 研究者能否据此说明主要经济业务、定位证据、识别重要未知；记录具体失败及返工 | 负责人完成固定任务并写理由；不能只填“感觉不错” |
| 成本与复核负担 | 模型调用成本、耗时、人工复核和返工时间分开记录 | 可核验日志与人工记录；未知成本写未知，不写零 |

这是首个可信测量版本，**不预设凭空的 95% 准确率或节省 50% 时间目标**。先得到完整分布和主要错误，下一版才针对固定任务设改进阈值；机械完整性仍按 H1–H8 严格验收。

可以以固定小节的人工流程做用时对照，但阅读过同一资料会产生熟悉效应，必须披露；没有对照时只记录耗时，不声称效率提升。

### 5.3 baseline 暴露、预算与实验纪律

- 当前执行者已读过旧候选，本版不宣称盲测。登记旧候选、prompt 和人工反馈的暴露范围；运行端仍严禁读取 Gold。
- 在新的完整 Gold 结果揭示后改过 prompt/流程的运行须另编号为实验，不能回称初始 baseline。没有可信未调优版本时如实记录，重新冻结一个可解释起点。
- 在 G0 阶段登记开发示例和后续未用于调优的样本策略；单公司单文件的本版仅证明局部能力，不作跨公司泛化结论。
- 最小实验计划是一条 baseline 与一次单因素实验。执行前填写 provider/model、token/轮数/工具预算、总费用上限及失败重试上限；预算未定义时保留离线验证，付费运行不启动。
- 不能只保留最好一次。若因服务故障重试，记录原失败、费用和重试原因；如果增加种子或重复运行估计方差，预先固定数量并报告全体结果。
- Gold 修正必须升版，对 baseline 和实验双方重新评分；原结果留存。

## 6. 交付目录与版本结论

沿用既有数据命名空间，新增真实内容时再创建版本目录：来源在 `data/source_documents/`，人工基准在 `benchmarks/`，模型执行在 `data/agent_runs/`，实验记录在 `experiments/`，人工复核与评分在 `data/evaluation/`。入口和配置应显式引用版本，不依赖“latest”猜测。

对于不随 Git 发布的资料，提供 manifest、校验方式和可访问的获取/导入步骤。只有说明“需要原电脑的文件”不满足本版独立重放要求。

使用 [验收模板](ACCEPTANCE_TEMPLATE.zh-CN.md)分别填写：

- 工程交付是否通过；
- 人工研究参考是否通过；
- baseline 与实验质量是多少、有什么限制；
- 哪些自动化能力仍是实验性；
- 是否允许进入下一里程碑。

只要参考、测量和实验可核查，即使 baseline 很弱或实验无改善，也可以完成本版“建立研究基线”的目标。输出质量不足的系统不得因此被标记为可直接用于投资决定。

## 7. 第一个执行批次

先完成 **V2-01 → V2-02 → V2-03/04 → V2-05**：列清输入、取得完整指定年报、处理定位问题、拿一个小节完成真实人工试用，再冻结公共输入输出、来源边界与 baseline 设计登记。提交 R2-A 的完整证据后再进入人工 Gold。

开始时需要在任务记录中落实的执行参数：来源存放方式、人工复核的实际负责人、baseline 模型和实验预算。当前计划不假定这些参数已经确定，也不虚构日期或人工签收。
